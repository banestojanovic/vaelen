# Vaelen verification map

These journeys form the verification map. A recipe is coverage only after a recorded execution. Read the entry for the changed behavior before selecting a focused check.

| Journey | Automated production entry point | Isolated or simulated boundaries | Manual GUI review | Not yet verified by this skill |
| --- | --- | --- | --- | --- |
| [List linked projects](links.md) | Real `val links` child, Unix socket, Core dispatcher, SQLite | Six seeded projects; disabled router, DNS, TLS trust, privileged ports | Linked-project GUI remains manual | Installed app, real routing, full PHP-FPM, CLI link creation |
| [Choose project PHP](project-php.md) | Real Core client serialization and dispatcher | In-memory transport, synthetic PHP package metadata | Project PHP GUI remains manual | CLI selection mutation and GUI interaction |
| [Choose project Node](node-project-selection.md) | Real offline `val node exec` child, Core dispatcher codecs, and opt-in shell wrapper forwarding | Temporary state, PATH stand-in, contained archive fixtures; optional real official arm64 packages | Native Node selector presentation and interaction require manual review | Installed-app acceptance and full Core CLI selection lifecycle |
| [Update PHP](php-update.md) | Dispatcher and socket lifecycle tests exist | Cached real PHP pair, private roots, router doubles | Update GUI remains manual | Not executed by the initial proof; cache required |
| [Browse Settings inventory](settings-inventory.md) | Core presentation model functions | Pure classification, counts, and selection fixtures | Core-backed Settings interaction and rendering require manual review | No GUI interaction proof |
| [Run Composer](composer.md) | Real `val composer` child, private Core PHP resolver, PATH script lookup | Synthetic arm64 Mach-O PHP stand-ins and Composer script stubs | No GUI interaction | No real PHP interpreter or Composer behavior |
| [Inspect managed logs](logs.md) | Real `val logs` child over a private Core Unix socket | Temporary log fixtures and isolated Core state; no services started | No GUI interaction | Installed Core/app integration and live service logs |
| [List managed services](service-list.md) | Actual `val service list --json` child against missing Core, a complete private Core, and a partial private Core with `mysql: nil` | Empty temporary package layout; no MySQL or Mailpit process and no service operations | No GUI interaction | Incompatible handshake, installed-app integration, live package or service health |
| [List managed service versions](service-versions.md) | Actual `val service versions` child for both types through private Core; native typed JSON payload comparison | Empty temporary package layout; no MySQL or Mailpit process and no service operations | No GUI interaction | Installed-app integration, package installation, live package or service health |
| [View managed logs in the app](managed-logs.md) | Injectable viewer state model with controlled asynchronous replies | Fake Core client; race and state mapping tests | Window interaction, clipboard integration, and light/dark appearance remain manual | Live managed logs and GUI rendering |
| [Manage local HTTP proxies](local-http-proxies.md) | Actual `val proxy` child with private Core socket, restart persistence, official isolated Caddy forwarding, and redirect refusal | Fake router for CLI lifecycle; separate real Caddy with owned local upstream and loopback redirect pair | Settings UI interaction remains manual | Installed-app acceptance |

The initial proof executes only the links success, controlled mismatch, and owned-child timeout checks. Supplemental runs must record exact commands, status, selected and passed counts, and skips. A skipped prerequisite or zero matching tests is not success. `docs/cli/herd-parity.md` lists intended counterparts, not evidence that they were exercised.
