# Site CLI commands — Slice 2A manual test sheet

Commands: `parked`, `sites`, `site driver`, `open`, `db`.

## Contract

- `val parks` lists persisted parked roots. `val parked` lists every Core project with `parkedFolder` provenance, including projects also explicitly linked, exactly once. Human output labels those `Linked · parked`; JSON preserves Core relationship/source fields. Unavailable roots are reported separately.
- `val sites` starts from every persisted route intent. JSON `caddyRouteObserved` means the exact hostname/target/TLS configuration was observed in Caddy. It is not proof that an HTTP request succeeded or that a project is healthy. Observation is nullable when Caddy cannot be inspected; project availability is independent.
- `val site driver [project]` reports detected framework/confidence/evidence separately from every configured route target/TLS and its exact Caddy route observation. Zero routes is explicit; multiple routes are listed, not guessed. Unknown framework and unavailable observation are distinct. Caddy observation does not establish HTTP reachability.
- `val open [hostname|project]` passes one exact selected URL to macOS `open`; TLS mode determines `https` versus `http`. Without a selector, the current directory must match exactly one route. Project names and projects with multiple routes fail closed.
- `val db [project]` uses `ProjectDatabaseViewerAction.tablePlus`—the same database selection and eligibility policy as the menu-bar button. It does not print the TablePlus URL, username, password, or other credentials.

## Temporary-fixture acceptance plan

1. **Empty discovery:** create and park an empty temporary workspace; `val parked` returns “No sites discovered…” while `val parks` contains that root. Unpark in cleanup.
2. **Unavailable folder:** in a fixture-only isolated Core registry/SQLite test, register then remove the temporary root; `val parked --json` (or the registry projection feeding it) identifies the missing root under `unavailableFolders`, not as an unexplained empty list. Never remove a real workspace.
3. **Park-discovered and linked site:** create a Laravel marker fixture under a temporary parked workspace; `val parked --json` returns it as discovered/parked without assigning a durable project ID. Explicitly link that same child, then check human and JSON output still include it exactly once and identify its linked-plus-parked relationship. `val sites` shows its configured route and independent Caddy observation. Unlink/unpark afterward and verify fixture files remain.
4. **Explicitly linked site:** link a separate temporary project; `val site driver <path>` reports the detector's driver/evidence. `val sites` presents it once as linked. Unlink in cleanup and verify the directory remains.
5. **Ambiguous current directory:** temporarily add a second hostname for the linked fixture, run `val open` from its root, and assert it exits nonzero without invoking `/usr/bin/open`; then remove only that test route.
6. **Exact open URL:** run `val open <fixture-hostname>` and confirm macOS opens the exact configured host and scheme. Do not claim browser dispatch from URL-construction tests alone.
7. **Database eligibility/privacy:** use fixture `.env` files only for negative cases. Try a missing database name, remote/unsupported driver and unavailable service/app; expect the shared projection's helpful reason and assert a distinctive fake password never appears in stdout/stderr. For the positive installed case, open the selected project's intended database in TablePlus, verify the correct connection/schema is selected, and issue no writes or edits.
8. **State and GUI:** with Vaelen Settings and menu-bar UI open, compare their project/site rows with `val links`, `val parked`, and `val sites`. After cleanup, compare all five baseline routes, five linked projects, and the exact pre-existing parked-root record; all must be unchanged.
9. Confirm `val doctor` is Healthy and `https://syncproof.test` returns HTTP 200 with TLS verification 0.
