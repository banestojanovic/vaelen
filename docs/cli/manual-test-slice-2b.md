# Site relationships and multiple hostnames — Slice 2B manual test sheet

## Contract under test

- `val link [project-directory] [--host HOST]` links the project and either ensures its default hostname (no `--host`) or adds the exact requested hostname. A hostname already routed to this project is idempotent; a hostname owned by another project fails closed.
- Every hostname is a separate route with its own route ID, target, and TLS mode. Adding one route must not rewrite any existing route record. If all existing project routes agree on target and TLS, a new custom host inherits that common configuration. If targets differ or TLS modes differ, `val link --host` fails closed rather than selecting the first route; use `val route add HOST DOCUMENT_ROOT --project-id ID [--php-socket SOCKET] [--tls]` to specify the new route explicitly. With no existing route, the detected framework/current healthy runtime selects the target and TLS defaults to HTTP.
- `val secure HOST` and `val unsecure HOST` select that exact route. With multiple project hostnames, no-host secure/unsecure and `val open` from the project directory remain ambiguous and require an exact hostname. Explicit open/secure/unsecure operate on the chosen route only.
- `val unlink PROJECT` removes Vaelen's explicit project relationship only. It does not delete files or routes. `val route remove ROUTE-ID` removes exactly one hostname, leaving other routes untouched. Park-folder provenance is independently owned by the parked-folder relationship and must not be removed by project unlink.
- Settings project rows show all configured hostname/TLS pairs. Menu-bar project cards offer explicit per-host opening when more than one exists. This presentation must not use a single selected report route to hide additional configured hosts.
