# Herd CLI parity matrix

Scope: every command documented in Herd's macOS [Command Line](https://herd.laravel.com/docs/macos/advanced-usage/herd-cli) page, grouped exactly as Herd presents it. This is a living acceptance ledger, not a claim that help text implies working behavior. Runtime acceptance for Slice 2B is recorded in `artifacts/cli-slice2b/`. Herd reference checked 2026-09-26.

## Reading this matrix

- `working` = an implemented Vaelen operation backed by Core, a native macOS integration, or a real child process; parse/help alone is not working behavior.
- `partial` = useful behavior exists but does not yet preserve all of Herd's semantics or requested acceptance.
- `missing` = no supported implementation. Do not add the command to `val list` until its underlying behavior exists.
- UI column is a counterpart, not proof of parity. Menu-bar and Settings state must continue to reflect Core.
- Side effects call out persistent/system changes. Acceptance tests must use temporary fixtures or isolated service instances before touching real project state.

## Existing Vaelen CLI audit inventory

This inventory separates implemented commands from discovery/help. All commands below have executable cases in `Sources/VaelenCLI/main.swift` unless explicitly labeled local integration. Their exact complete grammar is printed by `val COMMAND --help`; the focused subcommand details are enumerated here. **Normal command success:** exit 0. **Core unavailable:** exit 3. **Core protocol incompatibility:** exit 4. **Remote/local operation, invalid syntax, and unknown command:** currently exit 1 (invalid syntax emits usage; unknown names emit an actionable “Run val --help” error). `val php exec` propagates the child exit status. `--json` preserves existing IPC JSON envelopes; single-value PHP path resolution is plain text. Option parsing has been tightened for status and catalog/list JSON flags so unknown extra tokens no longer silently select human mode. This is source/test audit plus installed checks; operational failure modes are not implied by parser tests.
